## 원시 타입 vs 객체 타입 나눈 이유

 -> 값이 저장되거나 복사되는 과정이 서로 다르기 때문

### 원시 타입

 : 값 자체가 변수에 저장되고 복사

### 객체 타입

 : 값 자체가 아닌, 값에 접근할 수 있는 주소 값(참조 값)
 을 통해 변수에 저장되고 복사



원시 타입에서 값을 수정하면, 해당 메모리에 들어있는 값이
수정되지 않고, 새로운 메모리에 수정된 값을 넣어서 그 메모리를 가리키게 합니다.

이렇게 메모리의 값이 수정되지 않는 것을 불변값이라고 합니다.
(값을 수정하면 그냥 바꿔쓰지 않고 새 메모리를 찾음)

p1 = 1   // 메모리 하나 잡아서 거기 1 넣음 
p1 = 2   // 이전 메모리 버리고 새 메모리에 2 넣고 참조



## 객체 타입은 위와 다름.

메모리 어딘가에 값을 저장해놓고 변수의 메모리에는
그 값이 저장된 메모리 공간을 가리키는 주소값을 넣어줍니다.

```
let o1 = { name : "민경"};

// o1에 해당하는 메모리에는 주소만 들어있음
```




## 이렇게 하는 이유?

# -> 1. 크기와 구조가 가변적이라서

 원시 타입(number, boolean 등)은 크기가 고정적입니다. (예: 8바이트)

 객체는 속성이 추가·삭제될 수 있고, 내부 구조와 크기가 계속 변할 수 있습니다.

 그래서 변수 안에 직접 값 전체를 넣어버리면, 크기를 맞추기 어렵고 메모리 관리가 복잡해집니다.

 대신, 변수에는 고정 크기의 "주소값"만 저장하고, **실제 데이터는 별도의 힙(Heap) 영역**에 둡니다.



##  왜 변수 안에 직접 객체 전체를 넣으면 크기 맞추기가 어렵고 메모리 관리가 복잡해지는지 ##

### 메모리 구조(스택 vs 힙) 차이와 관련! ###

**1. 스택(Stack) 메모리는 고정 크기 저장소 **
   스택은 정해진 크기의 블록을 빠르게 할당·해제하는 데 특화되어 있습니다.

- 변수를 스택에 올리면, 해당 변수의 크기가 컴파일 타임 또는 실행 시점 초기에 고정되어야 합니다.
- 원시 타입은 크기가 정해져 있어서 문제없지만, 객체는 속성을 추가하거나 값을 바꿀 때 크기가 달라질 수 있습니다

**2. 객체 크기는 예측 불가**

- 객체를 스택에 직접 넣어버리면, 새로운 속성을 추가할 때마다 스택 메모리의 다른 변수들까지 밀어내거나 재배치해야 합니다.
- 스택은 이런 크기 변화를 처리하는 데 매우 비효율적입니다.

### 해결 방법: 주소만 스택에 저장 ###

객체는 힙(Heap)이라는 유연한 메모리 공간에 저장합니다. 힙은 크기 조정이 자유롭습니다.

변수에는 힙의 시작 주소(참조값)만 스택에 넣습니다.

속성을 늘리거나 줄일 때는 힙 안에서만 메모리를 조정하면 되므로, 스택에 있는 다른 변수에는 영향을 주지 않습니다.

## 📌 정리 ##

스택은 빠르지만 크기가 고정된 저장소라, 크기가 변할 수 있는 객체를 직접 담기엔 부적합합니다.
그래서 객체는 크기 조절이 자유로운 힙에 두고, 스택에는 주소만 저장하는 구조를 사용합니다.



## 그럼 왜 스택이 메모리 크기 변화에 취약? ##

### 1. 스택은 공간이 작고 고정적 ###

**스택 영역**은 운영체제가 프로그램 실행 시 미리 정해진 크기를 할당합니다.
(대부분 수 MB 단위, 예: 1~8MB 정도)

**힙 영역**은 훨씬 크고, 동적으로 확장할 수 있습니다.
(수백 MB~수 GB까지 가능)

- 그래서 스택 안에 대용량 데이터나 크기가 변하는 구조를 두면 금방 공간이 부족해집니다 → Stack Overflow 위험.



### 2. 스택의 메모리 관리 방식 ###

**스택은 LIFO(Last In, First Out) 구조**라,
변수가 선언될 때 정해진 크기만큼 스택 포인터를 위로 올리고,
함수가 끝나면 그대로 아래로 내려서 한 번에 해제합니다.

이 말은 **중간에 크기를 바꾸거나 확장하는 게 사실상 불가능하다는 뜻**입니다.
만약 중간 데이터 크기를 늘리려면 그 아래에 있는 다른 변수들을 모두 밀어내야 하는데,
이건 스택 설계 원리에 어긋나고 매우 비효율적입니다.







# -> 2. 공유와 참조를 가능하게 하기 위해

 객체는 용량이 클 수 있어서, **매번 복사하면 성능이 떨어집니다.**

 **주소(참조)만 넘기면** 여러 변수가 같은 객체를 공유할 수 있습니다.

```
let o2 = o1; // 주소 복사
o2.name = "가인";
console.log(o1.name); // "가인" (같은 객체 참조)
```

이렇게 하면 대용량 데이터를 효율적으로 다룰 수 있습니다.


# -> 3. 불필요한 메모리 낭비 방지

객체를 통째로 변수에 저장하면, 크기가 크든 작든 스택(Stack) 메모리가 급격히 늘어납니다.

대신 변수 → 주소 → 힙 메모리 구조로 하면, 스택에는 고정 크기(주소)만 차지하므로 효율적입니다.



## 정리

객체는 크기와 구조가 변할 수 있고, 공유가 필요하며, 메모리 효율성을 위해
변수에는 주소만 저장하고, 실제 값은 힙 영역에 따로 보관합니다.


# 원시 vs 객체 다른 점 2번째

**객체 타입 == 가변값**
: 원시 타입은 별도의 메모리에 새 값을 다시 저장한다면, 객체 타입은 메모리값 자체를 수정한다.

```
let o3 = {name : "cyreene"};
let o4 = o3;
// 이렇게 하면 o3의 참조값을 o4도 참고하고 있게 됨

o4.name = "민경";
// o4의 참조값을 통해 메모리에 접근해서 해당 값을 수정하면 o3도 같은 메모리를 참고하고 있었기 때문에
// o3(원본)로 접근해도 값이 수정된 것을 알 수 있다. (이래서 가변값임)

// --> 이런 식으로 변수를 수정했는데 다른 변수의 값도 함께 바뀌어버리는 걸 side effect라고 함
```



**원시 타입** : 불변값 (메모리 값 수정 x)
**객체 타입** : 가변값 (메모리 값 수정 o)




## 주의할 점

### 1. 의도치 않게 객체 타입의 값이 수정될 수 있음. (얕은 복사일 때)

# Node.js 소개

## 왜 Node.js를 배워야 할까?

React.js라는 기술은 Node.js를 기반으로 동작하는 기술이기 때문이다.

(Next.js, Vue.js, Svelte 또한 Node.js 기반)





## Node.js

: 웹 브라우저가 아닌 환경에서도 자바스크립트 코드를 실행시켜주는, 자바스크립트의 런타임(a.k.a 실행 환경, 구동기)이다.

- 언어를 구동하는 구동기를 실행 환경, 즉 런타임이라고 한다.



## 자바스크립트의 히스토리

자바스크립트는 웹페이지 안에서 일어나는 아주 단순한 기능만을 개발하기 위해서 만들어진 간단한 스크립트 언어

- 웹에서 버튼을 클릭하면 경고창을 띄워주거나, 요소의 색상을 변경시킨다던가 하는 단순한 인터랙션을 개발하기 위한 목적으로 개발되었다.
- 때문에, 동시대에 존재했던 C언어나 자바 언어와는 다르게 그 문법 자체가 유연하고 작성하기가 편리하게 설계되었다.
- 개발자들이 최대한 빠르게 개발할 수 있도록 생산성에만 중심을 두고 설계되었다.
- 인기가 많아지자 이제는 웹 브라우저 바깥에서도 자바스크립트를 이용해서 프로그램을 만들고 싶어했고 Ndoe.js가 등장했다.
  - (자바스크립트는 어디서든 동작할 수 있게 되었음.)

##### 자바나 C 또는 C#과 같은 언어로 만들던 웹서버는 이제는 자바스크립트로 구축되는 일이 많아졌다. (넷플릭스, 에어비앤비 등)

- 나아가, 모바일 앱을 만들고 (페이스북, 인스타 등)
- 데스크탑 앱도 만들었다. (슬랙, 디스코드 등)





# 정리

- Node.js는 아주 단순한 상호작용만 개발할 수 있었던 언어인 JS를 범용적으로 사용할 수 있도록 도와주는 JS의 실행 환경, 즉 런타임
- React는 이 Node.js를 기반으로 동작하는 기술

## **라이브러리란?**

: 프로그램을 개발할 때 필요한 다양한 기능들을 미리 만들어 모듈화 해 놓은 것

- npmjs.com (node.js 라이브러리 많음)



npm i ~~ 명령어로 라이브러리를 설치하면 **json의 dependencies에 해당 라이브러리가 추가**된다.

- 해당 프로젝트가 해당 라이브러리를 사용하니까 의존하고 있다는 뜻
- 그 라이브러리가 있어야 동작할 수 있다.



라이브러리를 설치하면 package-lock.json이라는 파일과 node_modules라는 폴더가 새로 생긴다.

- node_modules : 설치한 라이브러리가 실제로 저장되는 곳
- package-lock.json : 패키지가 사용하고 있는 라이브러리들의 버전이나 정보를 package.json 파일보다 더 정확하고 엄밀하게 저장하는 파일



#### 만약 package-lock.json이 지워지면 모듈 파일을 삭제했기에 오류가 뜬다

하지만 이때 package.json에 dependencies 저정보가 있기 때문에 라이브러리를 다시 설치할 수 있다.

- npm i
  - 이 명령어를 쓰면 package.json의 dependencies의 정보를 기준으로 모든 패키지, 모든 라이브러리를 다시 다 설치해준다.
  - 따라서, 이 명령어를 통하면, 한 번 설치되어서 package.json에 기록된 라이브러리들을 다시 설치하기 때문에 node.js 패키지를 압축해서 누군가에게 공유하거나 깃허브에 업로드할 때 node_modules 폴더는 굳이 함께 포함하지 않는다.
